# codewalk

読みたいリポジトリのパスを1つ渡すと、そのソースコードを**処理が通る順に1ファイルずつ読み解くWebサイト**を、作れるキットです（Claude code必要）。手元で見る、自分専用のサイトです。**公開はしません**。

```text
/codewalk <パス>              初回：①章立てを作って1度だけ確かめ、1章ずつ ②→③ と仕上げる
/codewalk                     続き：要見直しの章を直し、まだ作っていない章を仕上げる
/codewalk-update [コミット]    分析対象が進んだら：基準コミットを上げて、メモとサイトを合わせる
```

中では3つの工程を順に行います。工程ごとのコマンドもあり、1章だけ直したいときなどに使えます。

```text
① 調べる   /codewalk-setup <パス>   → workspace/codewalk.config.json（どこの・どの時点を読むか）
                                      workspace/notes/plan.md（どの順に・何章で読むか）
② 事実メモ  /codewalk-notes          → workspace/notes/NN-slug.md（主張と根拠の箇条書き。機械とレビュー役が照合）
③ サイト   /codewalk-site           → workspace/chapters/NN-slug.mdx（メモを資料に、見せ方だけ考える）
```

サイトの章は、左にファイル全文、右に解説を並べます。解説を読み進めると、いま読んでいる段落が指す行が光ります。章のページの左には全章と節の目次が出ます。コードはリポジトリから写さず、基準コミット（解説の対象にする、ある時点のコミット）から `git show` で取り出すので、表示されるコードは常に実物と一致します。

- ②のメモは、主張の1つ1つに根拠（コードの行・文書・コミット）を付けます。根拠の位置は**アンカー**（その行に含まれる文字列）で指し、機械が基準コミットと照合します。根拠が主張を支えているかは、別のエージェントが読んで確かめます
- 裏づけの無い主張は「推測」と明示します。サイトでも断定しません
- ③の検証は、サイトが言っていることがメモにあるか、表示したコードが実物と1行も違わないか、メモの節を全部扱ったかを見ます

書式の詳しい決まりは [format.md](.claude/skills/codewalk-notes/format.md) にあります。

## 必要なもの


| もの                                            | 用途                                                                                           |
| --------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Node.js 22.12 以上                              | サイトのビルドと検証（Astro の要件）                                                                        |
| git                                           | 対象のリポジトリを読みます。中身の履歴も残します                                                                     |
| [Claude Code](https://claude.com/claude-code) | 3つのスキルを動かします                                                                                 |
| Google Chrome（任意）                             | 見た目の検証（`check:visual`）に使います。macOS 以外や別の場所に入れているときは、環境変数 `CHROME` で場所を指定します。無ければ、その検証だけを飛ばします |


読みたいリポジトリは、手元に clone してあれば十分です。**キットは対象のリポジトリの作業ツリーに一切触りません**（checkout も fetch もしません。`git show <コミット>:<path>` で読むだけです）。対象のスクリプトを実行したり、依存をインストールしたりもしません。対象の README やコメントに書かれた指示にも従いません。

## 使い方

```bash
git clone <このリポジトリ> my-codewalk
cd my-codewalk
npm --prefix site ci
claude                                   # リポジトリのルートで Claude Code を開く
```

Claude Code の中で：

```text
/codewalk ~/src/some-app                 # 章立てを作り（1度だけ確認される）、全章を1章ずつ仕上げる
/codewalk ~/src/some-app --chapters 3    # 同じ。ただし3章仕上げたところで止める
/codewalk                                # 続きから（止めた所・要見直しの章・まだ作っていない章）
```

章が多い対象では、1回の実行が長くなります。`--chapters N` で区切って進めると、様子を見ながら続けられます。進み具合は `npm --prefix site run check:progress` で見られます。

工程ごとに動かすときは：

```text
/codewalk-setup ~/src/some-app           # ① workspace/ を作り、章立てを作る。最後に章立てを1度だけ確認される
/codewalk-notes                          # ② 次の章の事実メモを書く（/codewalk-notes 03 や 03-07 も可）
/codewalk-site                           # ③ メモから次の章を作る（/codewalk-site 03、03-07、stale も可）
```

作成されたWebを見るには（リポジトリのルートで）：

```bash
npm --prefix site run dev                # http://localhost:4321 が開く
```

章立ては1回、メモとサイトは1章ごとに、`workspace/` のリポジトリへコミットします（プッシュはしません）。途中で止めても、済んだ章は残り、`/codewalk` で続きから進められます。スキルはスラッシュコマンドで呼んだときだけ動きます。

## どこに何があるか

あなたが作る中身はすべて `workspace/` にあります。`workspace/` はキットの Git に入らず（`.gitignore`）、**それ自体が独立した Git のリポジトリ**です。

```text
my-codewalk/                 キット（公開されていてよいもの）
├─ .claude/                  3つのスキルと2つのレビュー役
├─ site/                     サイトの仕組みと検証
└─ workspace/                あなたの中身（キットの Git の外。独自の Git の履歴を持つ）
   ├─ codewalk.config.json   対象のパス・基準コミット・題
   ├─ notes/                 plan.md（章立て）と、章ごとの事実メモ
   ├─ chapters/              サイトの章（mdx）
   └─ diagrams/              自分の章のために作った図
```

- Fork しても push しても、`workspace/` の中身はキットのリポジトリに入りません
- 中身の履歴は `git -C workspace log` で見られます。対象が更新されたときに「解説の何が変わったか」を差分で追えます
- 中身の控えを取りたいときは、`workspace/` に**非公開**のリモートを足して push できます（下の「中身を非公開のリポジトリで管理する」）



## 中身を非公開のリポジトリで管理する

`workspace/` は、キットとは別の**非公開**のリポジトリに push して管理できます。控えになるほか、別の端末で続きを書けます。キットのリポジトリ（公開されていてよいもの）とは分けたままにします。`workspace/` をキットの Git で追跡すると、`check` が失敗します。

GitHub に非公開のリポジトリを作り、`workspace/` のリモートにします（`gh` を使わないときは、GitHub の画面で Private を選んで作ります）。

```bash
gh repo create <名前> --private
git -C workspace remote add origin https://github.com/<あなた>/<名前>.git
git -C workspace push -u origin main
```

`workspace/` の pre-push フックが、push のたびに送り先を確かめます。非公開なら通し、公開なら止めます（`--private` を付け忘れたときなど）。

別の端末では、キットを clone してから、その中の `workspace/` に中身を clone します。**フックは clone では付いてこない**ので、入れ直します。

```bash
git clone <キットのリポジトリ> my-codewalk
git clone https://github.com/<あなた>/<名前>.git my-codewalk/workspace
npm --prefix my-codewalk/site ci
npm --prefix my-codewalk/site run hooks
```

対象のリポジトリも、`workspace/codewalk.config.json` の `repo` と同じ場所に clone します。場所が違うときは、環境変数 `CODEWALK_REPO` で上書きできます。

- 中身を置いたリポジトリは、後から公開に切り替えないでください（下の「公開しない」）
- 共同で作業する人を足すときは、その人にも対象のコードを見せてよいかを先に確かめます



## コマンド

リポジトリのルートで実行します。


| コマンド                                             | すること                                                                                             |
| ------------------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `npm --prefix site run check:notes [-- 03 04]`   | 章立てと事実メモの照合（書式、根拠のアンカーが基準コミットのちょうど1行に一致するか、コミットが祖先にあるか、判断の ID が実在するか）。推測の件数も出します                 |
| `npm --prefix site run check`                    | ビルドと検証（リンク、判断の ID、表示したコードと実物の一致、メモの見出しの抜け、メモが書き起こした後に変わっていないか、中身がキットの Git に入っていないか、pre-push フック） |
| `npm --prefix site run check:progress`           | 章ごとの進み具合（メモ・サイト・要見直し）と、次に作る章を出します。`/codewalk` が続きを決めるのに使います                                      |
| `npm --prefix site run check:stale`              | ビルドせずに「要見直し」の章（書き起こした後にメモが変わった章）と、メモの差分の見方を出します                                                  |
| `npm --prefix site run check:update [-- <コミット>]` | 基準コミットから新しいコミット（省くと最新）までの変わり方を測ります。章ごとに変わったファイル、消えた・増えたファイルと、追従か作り直しかの目安を出します。何も書き換えません          |
| `npm --prefix site run check:visual [-- 03]`     | 図をライト・ダークで撮影し、行の強調のずれと JS のエラーを確かめます。画像は `site/.shots/`（Git には入りません）                             |
| `npm --prefix site run hooks`                    | `workspace/` に pre-push フックを入れ直します（キットを更新したときなど）                                                 |
| `npm --prefix site run dev`                      | 手元でサイトを開きます（`npm --prefix site run dev:stop` で止めます）                                              |


**判断の ID** は、対象のリポジトリが設計の判断を記録している文書（ADR など）の見出しの番号です（`ADR-0003` など）。`workspace/codewalk.config.json` の `decisions` に設定すると、メモとサイトに書いた ID が実在するかを照合します。

## 対象が更新されたら

対象のリポジトリが先に進んだら、`/codewalk-update` を実行します。`/codewalk-setup` をもう一度実行するのではありません（書いたメモがあると止まります）。

```bash
git -C ~/src/some-app pull        # 新しいコミットを取り込むのは自分で（キットは対象で fetch しない）
```

```text
/codewalk-update                  # 最新（origin/HEAD、無ければ HEAD）に合わせる
/codewalk-update v2.1.0           # 指定したコミット・タグ・ブランチに合わせる
```

変わり方を測って（`check:update`）、次のどちらかで進めます。


| 進め方      | いつ                         | すること                                                            |
| -------- | -------------------------- | --------------------------------------------------------------- |
| **追従**   | 章立てがそのまま使える                | 基準コミットを上げ、変わったファイルやメモの根拠が指すファイルに当たる章だけ、メモとサイトを直す。確認は挟まない        |
| **作り直し** | ファイルの多くが消えた・増えた、処理の道筋が変わった | 新しい章立てを作って1度だけ確かめ、全章のメモとサイトを書き直す。前の版は `workspace/` の Git の履歴に残る |


アンカーが外れていなくても、中身が変わった主張はありえるので、追従でも差分に出たファイルに当たる章は全部見直します。サイトの章は frontmatter の `basedOn`（書き起こしたときのメモの、`workspace/` のコミットの ID）で、メモが変わった章を `check:stale` が挙げます。

## キットを更新する

キット側が直ったら、取り込めます。中身は `workspace/` にあるので、衝突しません。

```bash
git remote add upstream <キットのリポジトリ>   # 一度だけ
git pull upstream main
npm --prefix site ci
npm --prefix site run hooks                     # pre-push フックが変わっていても入れ直せる
```



## 公開しない

作ったサイトと中身は、手元だけに置きます。サイトは対象のファイルを**全文**表示し、メモにもコードの断片（アンカー）と内部の仕組みの説明が入るためです。非公開のコードや、コードに紛れた秘密の情報が外へ出るのを防ぎます。


| してよいこと                                                          | しないこと                                                   |
| --------------------------------------------------------------- | ------------------------------------------------------- |
| `npm --prefix site run dev` で手元のブラウザから見る（`localhost` だけで待ち受けます） | `--host` などで、ほかの端末から開けるようにする                            |
| `site/dist/` を手元で開く                                             | `site/dist/` をホスティング（GitHub Pages・Netlify・Vercel など）に置く |
| `workspace/` を、手元か**非公開**のリポジトリに置く                              | `workspace/` を公開リポジトリに push する                          |
| キット（`workspace/` を除いたもの）を人に渡す、Fork する                           | `workspace/` を含むフォルダを、そのままコピーや zip で人に渡す                |


守りは仕組みにも入れてあります。

- 開発サーバーと見た目の検証は、`localhost` / `127.0.0.1` だけで待ち受けます
- `workspace/`・`site/dist`・`site/.shots` がキットの Git に追跡されていると、`check` が失敗します
- `workspace/` の pre-push フックが、push のたびに送り先を確かめます。GitHub の公開リポジトリと、公開か非公開かを判定できない送り先（GitHub 以外、通信できないとき）は止めます。手元のパスと GitHub の非公開リポジトリは通します。確かめたうえで送るなら `git push --no-verify`、いつも許す送り先は `git -C workspace config --add codewalk.trustedRemote <URL>` で登録できます
  - フックが確かめるのは push する時点だけです。push した後で送り先のリポジトリを公開に切り替えると、それまでに送った中身がそのまま公開されます。`workspace/` を置いたリポジトリは、公開に切り替えないでください
- Astro の使用状況の送信（テレメトリ）は、キットの設定で切ってあります

キット自身には、どのリポジトリのコードも入っていません（例はすべて架空のものです）。

## 決まりと制約

- 1つの clone で、対象のリポジトリを1つ扱います。別のリポジトリを読むときは、別の場所に clone します
- 対象のリポジトリの場所が人によって違うときは、環境変数 `CODEWALK_REPO` で上書きできます
